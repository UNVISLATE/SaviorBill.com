## Архитектура LuaWorker

Все сценарии выдачи услуг, взаимодействия с внешними API, обработки вебхуков платёжных шлюзов и триггеров выполняются в изолированной песочнице **LuaWorker** (LuaJIT).

Ядро биллинга передает задачи воркеру через шину задач **Valkey Streams**. Скрипт получает только строго определённый контекст `ctx` своей задачи и возвращает детерминированный результат.

---

## Контекст услуги (Service Script)

Для скриптов выдачи услуг передаются следующие действия:
- `create` — первичная выдача и создание услуги во внешней панели;
- `renew` — продление срока действия подписки;
- `freeze` — временная приостановка (нехватка средств / блокировка);
- `unfreeze` — разморозка услуги после пополнения;
- `delete` — окончательное удаление и освобождение ресурсов.

### Пример контекста:

```lua
-- ctx структуры задачи
{
  action = "create",
  user = {
    id = 42,
    login = "UNVI"
  },
  service = {
    id = 25,
    slug = "vpn-license",
    settings = {}
  },
  order = {
    amount = "15.00",
    currency = "RUB",
    tier = "1_month"
  }
}
```

### Формат ответа:

```lua
return {
  public = {
    subscription_url = "https://example.com/sub/token123",
    qr_code = "vless://..."
  },
  private = {
    internal_user_id = "srv_9921"
  },
  state = "active",
  expires_at = 1760000000
}
```

- **`public`**: данные, которые автоматически передаются клиенту и рендерятся в личном кабинете покупателя;
- **`private`**: внутренние системные метаданные ядра (не показываются покупателю);
- **`state`**: статус услуги (`active`, `frozen`, `error`);
- **`expires_at`**: Unix timestamp окончания срока действия.
